## Finding 17 — cleanup trashes recovery-only audio (commit `7544b3f`)

**Confirmed in code (base `ed4642e`):** a save that fails half way through the replace keeps the new version as
`<song>.core.saving-N` (`storage.cpp:176`, kept at `:130-139`/`:192` when `previousFileIntact=false`).
`audioSavedSongsUse` (`assets.cpp:376-401`) matched only `.core`/`.core.bak`/`.json`/`.json.bak` (`:384-385`):
a retained `.saving-N` was skipped silently — not even "in doubt". Chain: `strayAudioFiles` (`:404-422`) →
`filesNoSavedSongNeeds` (`:424-433`) → Recycle Bin in `MainComponent.cpp:4221` (`removeUnusedAudio`, not edited).
Nothing else reads `.saving-N` back, so the retained copy can be the **only** reference to an audio file.

**Red (measured before the fix):** two new English-named tests in `tests/bug_tests.cpp` (before `CORE_TEST_MAIN`).
The main test builds two songs sharing one `Audio/` folder, then forces the D4 half-way failure with
`setReplaceStepForTests(failHalfWay)` (the existing precedent in the same file): `B.core`'s name is taken by a
directory, the previous version (no audio) is the `.bak`, and the new version — the only copy referencing wav X —
stays in `B.core.saving-N`. X is unreferenced by the open song.

Command: `ctest --test-dir D:/Core-build/flawless-preservation -R "bug_tests|midi_tests" --output-on-failure`
(log: `red-ctest.log` in the evidence dir). Key red output:

```

FALHOU ...bug_tests.cpp:577: filesNoSavedSongNeeds({audioX}, dir).size() == (size_t)0: medido 1, esperado 0
FALHOU ...bug_tests.cpp:583: stray.size() == (size_t)1: medido 2, esperado 1
bug_tests: 24 testes, 153 verificacoes, 8 falhas
```

X was listed as stray — "Remove unused" would have sent the recovery copy's only audio to the Recycle Bin.
The second test also measured red: an unreadable retained `.saving-N` did not raise doubt, and a retained
`core-project` copy's wav paths were not counted.

**Fix (minimal, `app/domain/src/assets.cpp` only):** in `audioSavedSongsUse`, a file name ending in
`.saving-<digits>` is read as the song it is a copy of: the suffix is stripped and the **same** format checks
apply (`.core`/`.core.bak` → Core document or doubt; `.json`/`core-project` → wav paths; a song-named file that
is not one Core reads → `return false`, in doubt, nothing goes). No change to `strayAudioFiles`,
`filesNoSavedSongNeeds`, the Recycle-Bin move, or `MainComponent.cpp`.

**Green (after the fix):** `bug_tests` 24 testes / 153 verificacoes / 0 falhas (was 22/138 at `ed4642e`;
+2 tests, +15 checks, none removed). The real orphan is still listed (D1 semantics intact).

## Finding 18 — invalid MIDI name Unicode makes the document unserializable (commit `e105488`)

**Confirmed in code (base `ed4642e`):** `cleanName` (`midi.cpp:293-310`) checked lead/continuation structure
only (`:297-299`): overlong `E0 80 80`, surrogate `ED A0 80`, above-U+10FFFF `F4 90 80 80` all passed.
The import guard `parseDocument(toJson(next))` (`:378`) never dumps, so the import succeeded; but
`saveFile` (`storage.cpp:201`, `.dump(2)`) and `writeAutosave` (`autosave.cpp:27`, `.dump()`) throw on invalid
UTF-8 (nlohmann 3.11.3 strict, `engine/third_party/json.hpp`). The existing test (`midi_tests.cpp:150-168`)
covered Latin-1/control bytes only. `renameTrack` (`edit.cpp:358-365`) also lacked UTF-8 validation.

**Red (measured before the fix):** two new English-named tests in `tests/midi_tests.cpp` (after the existing
name test, before `CORE_TEST_MAIN`). Six byte classes imported (overlong 3- and 4-byte, surrogate half,
above U+10FFFF, lead beyond F4, invalid bytes inside a plain name); import succeeds, then
`toJson(d).dump()` must not throw; round trip stable; `saveFile` + `openFile` verified. Plus `renameTrack`
with the same classes. Key red output (same ctest command, `red-ctest.log`):

```
FALHOU ...midi_tests.cpp:252: !threw        (x6 — one per byte class: nlohmann type_error.316)
FALHOU ...midi_tests.cpp:280: esperava excepcao: renameTrack(d, id, bad)   (x4)
midi_tests: 10 testes, 138 verificacoes, 15 falhas
```

**Fix (minimal):**
- `app/domain/src/midi.cpp` — `cleanName` now also rejects overlong forms (`E0` followed by `< A0`,
  `F0` followed by `< 90`), surrogate halves (`ED` followed by `>= A0`), leads beyond `F4`, and anything
  above U+10FFFF (`F4` followed by `>= 90`). Invalid bytes take the **existing Latin-1 fallback**; the
  80-byte cap, control-character handling and character-boundary cut are unchanged.
- `app/domain/src/edit.cpp` — `renameTrack` refuses a name that is not well-formed UTF-8 with
  `DocumentError("name", "is not valid UTF-8 text")` (file-local validator `wellFormedUtf8`); the song is
  left unchanged. Existing callers (`MainComponent.cpp:4775` through the `edit(...)` wrapper) already handle
  `DocumentError`; `MainComponent.cpp` was not edited. Existing `hunt_tests` rename cases use valid UTF-8
  and still pass.

**Green (after the fix):** `midi_tests` 10 testes / 150 verificacoes / 0 falhas (was 8/115 at `ed4642e`;
+2 tests, +35 checks, none removed). Round trip stable; save/reopen keeps the cleaned name; the Latin-1
fallback is pinned by an exact-byte check (`Kick` + `ED A0 80` → `Kickí ` as UTF-8 Latin-1 bytes).
Logs: `green18-build.log`, `green18-ctest.log`, `green18-suite.log`.
