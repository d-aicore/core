## BUG-SWEEP-03 — red, fix, green

Injection (the sweep's own probe, `core-audit-probes.cpp`): a directory obstructs the target AFTER the
original was moved aside, so both the placement and the restore-rename fail. The old code kept the bytes
(the `.previous` copy survived) but reported nothing: `published==0`, no rollback outcome, no backup path,
and the app still said "No existing file was changed."

The preservation checks (throw, `published==0`, target is a directory, `.previous` keeps the old bytes,
restore puts the bytes back when it can) already passed before the fix — the defect was the silence about
the outcome, exactly as the sweep reported. Full red output:
[03-red.txt](evidencia/2026-11-18-sweep-batch2/03-red.txt).

Fix (`9c457ab`, end to end):

- `engine/src/core/render_job.hpp`: new `PublishRollback { attempted, restored, backups }`;
  `publishRenderOutputs` gains an optional `PublishRollback*` out-parameter (default `nullptr`: the CLI
  call in `server.cpp:724` is unchanged and still gets the named copies through the error text).
- `engine/src/core/render_job.cpp`: the undo records every restore that succeeded (`restored`) and every
  old copy it could not put back (`backups`, the `.previous` paths — kept on disk, never deleted); the
  thrown error names the kept copies ("The previous file was kept as a copy: ..."), so the CLI and any
  other caller can recover them too. The job keeps the outcome; `describe()` on a failed job emits
  `rollbackAttempted`, `restored`, `backups` (alongside the existing `published`).
- `app/desktop/src/EngineSession.h/.cpp`: `ExportJob` gains `published`, `rollbackAttempted`, `restored`,
  `backups`; `readJob` parses them (type-checked).
- `app/desktop/src/MainComponent.cpp`: the failure dialog is conditioned on the REAL outcome — the
  "No existing file was changed." sentence only when no old copy was stranded; otherwise it says the
  previous files could not be put back, that every old copy was kept (named in the error above it) and
  how to recover them; a separate sentence names any new files left in place (`published > 0`).
- `lang/pt-PT.json`: three new `{}`-pattern entries cover the new sentences (alone and combined with the
  left-in-place count); the existing "No existing file was changed." entry still covers the honest case.
- `tests/audit2_tests.cpp`: the three red tests above, plus two unit tests pinning the `PublishRollback`
  contract directly (a two-file publish where one restores and one stays aside; a successful publish
  reports no rollback and uses the old copy up).
