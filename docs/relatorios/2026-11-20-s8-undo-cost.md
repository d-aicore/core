## Pendências e passagem — PROPOSTA shared-blob (NÃO implementada; decisão do dono)

**Design proposto (P-F-S8-SHARED):** snapshots do Document com **structural sharing**
(COW/shared_ptr nos blocos pesados — plugin state blobs, patterns), pricing por **contadores de
bytes mantidos no edit** (o documento já conhece os tamanhos via stateId/hasState do
state-per-edit) em vez de toJson+dumps; eliminar a serialização sameContent (comparação
estrutural ou hash de conteúdo mantido no edit). O state-per-edit (5df584f) já tornou a
projeção stateless — o undo é o custo restante declarado (slice 1).

**As TRÊS provas exigidas pelo dono se avançar (regressões esboçadas):**
1. **Independência entre snapshots**: mutar um snapshot nunca toca outro (teste: commit A, edit
   para B, verificar A byte-idêntico via sameContent/replay; partilha COW não pode aliasar mutação).
2. **Integridade undo/redo**: restauração exata do documento incl. plugin state + automação
   (o probe atual sameContent vs replay determinístico + blob-intact é a base; estender para
   snapshots partilhados, trim-aware).
3. **Respeito pelo limite de memória**: ceiling aplicado aos bytes REALMENTE retidos com
   accounting de propriedade partilhada (cada blob pesado contado uma vez enquanto referenciado;
   corrigir o gap S8-MEM — current_/saved_/transientes também preçados ou limitados).

**Ganho esperado (das medições):** commit t32_s318128 **151 ms → ~3.3 ms (~46×)**; undo/redo
semelhante; memória limitada pela retenção partilhada real (não 1.7× o ceiling). Ganho cresce
com o tamanho/número de blobs (t32_s1048576 415 ms commit).

**Defeitos candidatos registados (proposta, não corrigidos):** BUG-S8-MEM-ACCOUNTING (ceiling
só preço dumps, memória real ~1.7×); follow-up modified() per-frame (dirty-flag «08»). D-a
refutado. **Decisão do dono**: avançar shared-blob (com as três provas) ou aceitar o custo atual;
commit S8 docs; o custo é real mas não perde dados (integridade verde).
