## Incident — cross-worktree `git stash` collision (and recovery)

`refs/stash` is **repository-wide, shared by all worktrees**. During the before/after proof:

1. This session stashed the 4 L2 source files (`stash push -m "L2 before-after proof" -- <paths>`), built and
   ran the suite green on the pre-deletion tree (valid measurement).
2. The parallel crash stream pushed its own docs stash (README index line + untracked
   `2026-11-18-plugin-crash-followups.md`) on top. This session's `stash pop` therefore applied **their**
   stash into this worktree, and the crash stream's later pop applied **this session's** stash (the L2
   deletions) into `flawless-crash`. The "after" leg of the proof ran on a tree without the deletions and
   was discarded as contaminated.
3. Recovery (no other worktree edited): the deletions were re-applied from the exact saved diff
   (`git apply`, preserved as `l2-recovered.diff`) plus the two `samples.hpp` edits; `git diff --stat`
   verified identical to the displaced copy (443 deletions / 1 insertion). The crash stream's docs work —
   the only copy, uncommitted anywhere — was preserved byte-for-byte in
   `D:/Core-build/flawless-deadcode-evidence/stash-collision/` (`2026-11-18-plugin-crash-followups.md` +
   `readme-index-line.patch`) before restoring this worktree's README.md to HEAD. The crash worktree was
   later observed clean with HEAD unchanged (`8fcce35`): that stream discarded the foreign source changes
   itself. The after leg was re-measured green on the recovered tree, then L2 was committed.
4. No work was lost. **Recommendation: never use `git stash` in parallel-stream worktrees**; use per-worktree
   patch files or temporary commits instead. The crash stream's docs deliverable must be restored from
   `stash-collision/` (apply `readme-index-line.patch` to its README.md and restore the report file).
